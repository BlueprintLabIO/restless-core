# EXP-18: parallel-capacity crossover

**Status:** Draft; activation forbidden until Sprint 30 passes and the sealed manifest exists

**Date:** 31 August 2026

## Question

When work consists of many genuinely independent, locally closing economic units, does a supervised
parallel Restless team deliver materially more accepted output than one durable worker at quality and
cost parity?

EXP-17 did not answer this. Its account workload used one worker in both arms, so supervision added
overhead without adding capacity.

## Hypothesis

A parallel team should win when all four conditions hold:

1. units do not share mutable artifact state;
2. each unit has a local contract and gate;
3. workers can deliver directly without semantic synthesis; and
4. provider and machine capacity permit actual concurrent production.

If any condition is absent, one durable worker remains the default.

## Frozen first comparison

### Workload

Forty-eight synthetic account opportunities, frozen before activation. Each dossier contains a distinct
company, evidence packet, contact constraints and required next action. A unit closes independently as
one policy-compliant account brief, evidence map and recommended action. There are no live messages,
CRM writes, purchases or external effects.

All 48 units run the same native schema, citation, source-isolation and policy gates. The final output
is a mechanical content-addressed index of unit receipts, not a prose synthesis.

### Arms

- **S1: single worker.** One durable worker owns all 48 units sequentially in one bounded queue.
- **P4: parallel team.** One accountable non-producing lead freezes four disjoint 12-unit partitions.
  Four identical workers run concurrently with separate workspaces, request identities and budgets.
  Workers publish unit receipts directly. The lead wakes only for a material exception and does not
  merge or rewrite outputs.

Exec delegates exactly once in P4 and returns to availability. Both arms use the same exact model,
reasoning effort, tool surface, per-unit brief, source bytes and total unit set. Order, opaque labels,
arm order, provider concurrency, ceilings and reviewer sample are sealed before execution.

## Why there is no generic fan-in

The economic outcome is 48 accepted account decisions, not one essay about the accounts. Mechanical
collection verifies completeness and digests. A semantic assembler would create a new coupled task,
blur authorship and charge coordination overhead unrelated to the tested capacity hypothesis.

## Measures

Primary:

- accepted units per wall-clock hour;
- elapsed time to 48 terminal units;
- blind quality on the frozen stratified sample; and
- spend per accepted unit.

Secondary:

- first-unit latency;
- producer active time and cached tokens;
- failed/retried units and policy violations;
- lead wakes, interventions and decision latency;
- request-accounting failures, worker/process replacements and manual rescues; and
- fan-in model turns and rewritten worker bytes, both expected to be zero.

Unknown telemetry remains unknown and blocks claims that depend on it.

## Quality and review

Native gates run on all 96 arm-unit outcomes. Before activation, select a stratified hidden sample of
12 unit identities covering policy and evidence difficulty. Two fresh source-blind reviewers compare
opaque outputs using one frozen rubric. Review runs are sequential per settlement identity unless
Sprint 30 proves independent concurrent accounting.

An unreadable bundle, arm leak, metering ambiguity or reviewer exposure invalidates only the affected
review and must be repaired before any reveal. Review programme spend is reported separately from
production overhead.

## Crossover rule

P4 wins only if all of the following hold:

1. all 48 units pass native gates and there is no serious policy or source-isolation blocker;
2. blind mean quality is within five points of S1;
3. elapsed time is at most 70% of S1, equivalent to at least 1.43x throughput;
4. spend per accepted unit is at most 1.5x S1;
5. owner attention, manual rescue and semantic fan-in are zero; and
6. every request and output reconciles exactly to its worker, partition, Attempt and company total.

Otherwise S1 remains the default for this load. Do not average this result with coherent coding or
longitudinal work.

## Sparse continuation

- If P4 wins, run one transfer pair on a different locally closing family, frozen before reveal. The
  preferred transfer is independent game-content validation units, not edits to one shared scene.
- If P4 loses on quality or coordination, stop. Do not search P2/P3/P6 after seeing outcomes.
- If the pair is infrastructure-invalid solely because actual provider concurrency was unavailable,
  repair capacity once and replay the same sealed pair. Do not change unit count or partitioning.
- If the first pair is valid and decisive, stop after the declared decision. Replication belongs to a
  later confirmation experiment, not post-outcome searching.

## Evidence and cleanup

Retain the activation manifest, starting digest, arm map, compact run ledger, native receipts, blinded
score hashes, invalidity rows, decision calculation and terminal cleanup receipt. Destroy companies,
databases, containers, request credentials, model homes, raw transcripts, review bundles and temporary
workspaces after synthesis.

## Claims forbidden

EXP-18 cannot establish that teams are generally superior, that parallelism helps coupled artifacts,
that supervision improves quality, or that simulated account briefs imply live sales effectiveness. It
can identify one measured capacity crossover for one genuinely parallel workload and load size.
