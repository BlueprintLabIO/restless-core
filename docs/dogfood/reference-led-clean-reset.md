# Reference-led clean-reset dogfood

## Purpose

Prove that Restless can respond to an owner-requested fresh start by commissioning a new landing-page
outcome from an exact clean source, ordered ground truth and a context allow-list—without inheriting a
rejected candidate as the solution template.

## Capability under test

The `reference-led-reset` lead skill uses existing Restless contracts deliberately:

- a new Work node rather than a same-Work revision;
- exact `base_ref` and a new Runtime-owned worktree;
- a non-repository reference-pack prerequisite as the only attached artifact source;
- a fresh Staff producer and fresh independent critic;
- factual native web review followed by lead and owner judgement; and
- ordinary Work/Attempt/artifact/revision lineage rather than a workflow DSL.

## Success evidence

1. The producer's Attempt context records the exact clean Cloud base and only allow-listed inputs.
2. The producer does not inspect the rejected candidate or receive its rationale.
3. The resulting landing page is recognisably new while remaining faithful to the current Restless
   product design system.
4. The exact page runs at desktop and 390px mobile, supports reduced motion, builds cleanly and has no
   browser/runtime error.
5. A fresh critic compares product fidelity first and maturity second, and any repair returns to the
   producer.
6. The lead returns one exact live ReviewTarget and a bounded owner decision.

This dogfood does not authorise publishing, pushing, hosting changes or replacing a public deployment.
