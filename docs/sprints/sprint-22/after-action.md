# Sprint 22 after-action — provisional

## Result

The website-quality gap was real, and it was partly a Restless evaluation defect. Adding a mature
reference, complete rendered capture, a fresh critic and a non-producing lead materially changed the
Cloud result. The accepted candidate is deeper, more legible, more visual, route-complete and visibly
more mature without copying Neon.

## What worked

- A named maturity reference gave “good” observable structure: sustained narrative, product proof,
  complete responsive navigation and professional information architecture.
- Scroll-exercised desktop/mobile/reduced-motion evidence caught defects that source checks and naive
  full-page screenshots missed.
- Ordinary Work, Attempts, `requires`/`revises` edges and owner briefs were sufficient. No design-score
  entity or new workflow engine was needed.
- Recovery capsules preserved work across daemon interruptions, and the Runtime supervisor kept the
  final preview alive.
- The independent critic and lead made real judgements; deterministic gates remained factual.

## What failed or created friction

- A new company did not have a first-class way to materialize the authorised source repository. The
  run needed a Git bundle seed. Source materialization belongs in company commissioning, not prompts.
- Global historical model configuration affected admission for an unrelated test company. Admission
  must be company-scoped and stale company configuration must not destabilize active work.
- Daemon restarts interrupted agent sessions. The coordination daemon itself needs supervised,
  restart-aware operation with explicit drain semantics.
- A requested `inspect_image` tool exceeded the installed OMP tool surface. Capability negotiation
  should reject or adapt version skew before an actor launch; the S22 company used an isolated wrapper
  to remove only that unsupported token.
- A lead initially ran a monorepo gate from the worktree root although the package lived at
  the then-interim `apps/public` intake path (now canonicalised to `site/`). Gate working directories
  should be explicit data, not prompt inference.
- ReviewTarget selection happened inside evidence URI de-duplication. Repeated attempt URLs therefore
  produced a valid handoff with no openable outcome. Attempt selection and presentation de-duplication
  are now separate.

## Retain, change, delete

- **Retain:** the web-native review tool/skill, mature-reference dossier, independent critic boundary,
  non-producing lead, exact-commit evidence and supervised preview.
- **Change:** source commissioning, daemon lifecycle/drain behaviour, tool capability negotiation,
  gate working-directory contracts and ReviewTarget projection tests.
- **Delete:** producer self-review as acceptance, detached preview processes, annotated review URLs,
  screenshot-exists quality claims and public implementation credits in primary site chrome.

## Remaining owner judgement

The owner still decides whether the exact local candidate is good enough. No acceptance, push,
deployment or public replacement is implied by the critic verdict.
