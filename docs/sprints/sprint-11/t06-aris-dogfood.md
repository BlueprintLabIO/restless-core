**Layer:** End-to-end slice across OrgIntel, Runtime, Authority and owner cockpit.

**Observed friction:** Component checks could not reveal that an agent used pipeline exit masking,
claimed four green gates, failed the real build, waited across restart and told the owner a
machine-doable push was unavailable. Only the live company run exposed the coupled failure.

## Outcome

First prove crash, gate, chronology and effect boundaries in a `_test` company. Then use Sonnet in
Aris for one real repository-backed publication: Exec delegates, Staff repairs, direct ordered gates
pass, Exec reviews, Authority publishes, provider/deployment state reconciles and the owner receives
the live native outcome.

## Acceptance

- `restless doctor -c aris` passes before the real run.
- Exec and Staff both use their explicit Sonnet preference; any failover remains separately recorded.
- At least one failed gate produces a repair Attempt and later direct green gate evidence.
- The final branch/commit, effect receipt, GitHub state, deployment state and public URL probe agree.
- The owner can follow the chronological run and is never asked to execute a machine-doable command.
- The run report names observed inputs/outputs, false claims caught, owner attention consumed,
  economic outcome, remaining uncertainty and every abstraction/path deleted.
- No simulated provider or fabricated marketplace result enters Aris evidence.

## Deletion

Completing the ticket removes any losing prompt patches, duplicate Git wrappers, polling path,
non-chronological trace and temporary comparison branch that did not improve the real outcome.
