# Sprint 44 T5 — Decide the position and purge unsupported product surface

**Layer:** Product decision

**Serves:** An honest release claim and a smaller, supportable product.

## Work

- Have a fresh reviewer judge the blinded outcome packets and audit the unblinded operational evidence.
- Make an explicit founder decision for each major claim: strong, narrowed, or rejected.
- Choose release dispositions for Codex takeover, Claude takeover, governed application roles, and the optional graphical workstation.
- Update product language and operator documentation so the released position matches the evidence.
- Purge experimental clients, duplicate abstractions, raw-key paths, unused compatibility shims, and test state that are not part of the accepted release.
- Record the next highest-value gaps without converting every gap into committed roadmap scope.

## Acceptance

- [ ] A reviewer who did not run the trials can reproduce the scoring decision from the evidence packets.
- [ ] The final position says where Restless is the better default and where direct native access remains appropriate.
- [ ] Every programme surface has a release, revise, defer, or remove decision.
- [ ] Documentation contains no stronger claim than the evidence supports.
- [ ] Temporary authority, companies, processes, sessions, prototypes, and credentials are purged or intentionally retained by policy.

## Makes deletable

- Open-ended “parity” work with no product decision.
- Experimental surface retained only because it was expensive to build.
