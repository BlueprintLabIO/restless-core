# S43-T0 — Decide desktop activation and placement

**Layer:** Product evaluation + architecture  
**Serves:** A full vendor desktop should exist only for repeated work that smaller native paths cannot serve.

## Work

- Collect at least three real high-value intervention cases across two outcomes after Sprints 40–42.
- Identify the exact missing UI/OS capability and compare a small Restless repair, host-native remote or
  SSH client, Runtime-installed client and existing Company Computer streaming.
- Verify current candidate platform support, licence/redistribution terms, authentication modes,
  managed policy, update behavior, state roots, network requirements and resource cost.
- Produce credential/data threat models and exact cleanup ownership for each viable placement.
- Record one founder decision: close negative, activate host-only or activate one Runtime candidate.

## Acceptance

The decision is backed by observed owner work and current upstream evidence. No later ticket begins
without one exact candidate, placement, benefit threshold and stop condition.

## Makes deletable

Desktop-app assumptions, placeholder launchers and “native GUI” as an unspecified roadmap item.
