## Thesis

Restless is not a superior agent harness. It is the persistent operating system for a company whose
work, responsibility, memory, authority and evidence survive whichever agent, human or application is
currently acting.

Codex, Claude Agent and Restless Managed are ordinary installed processes until Restless delegates a
turn to one of them. A process becomes a **harness** because it accepts a certified execution role:
Restless can launch it with exact policy, observe it, attribute it, interrupt it, resume or reconstruct
it, account for it and settle its outcome. The binary is not constitutionally special; the delegated
role is.

This programme removes the remaining abstraction trap. The owner normally works through Restless's
company-level experience, but can take direct control through the genuine harness or application when
low-level access is valuable, then return without losing the company around the session.

## Product position

The claim to earn is:

> Run the company autonomously. Take control of any piece of work when needed. Use the best agent or
> application without rebuilding the company around it.

Codex and Claude primarily organise an agent session. Restless organises the durable company before,
across and after those sessions:

- goals, Work, accountable actors and decisions outlive model processes;
- files, Git, browsers, applications and services accumulate in one company computer;
- the owner enters exceptions rather than continuously prompting every task;
- Authority owns credentials, budgets and consequential external effects;
- OrgIntel can recover, reassign, narrow or escalate work; and
- native access remains available when a managed abstraction is insufficient.

Multi-harness support is therefore an anti-lock-in and continuity property, not the main product
surface. Restless should sell useful company outcomes per unit of owner attention, not the number of
agent backends it wraps.

## Programme outcome

An owner encountering stalled, subtle or highly technical Work can select **Take the controls** from
the existing Attention, Work or active-session context. Restless checkpoints the exact workspace,
pauses autonomous ownership at a safe boundary and opens the most native supported client against the
same harness session where the provider permits it.

The owner can inspect and intervene through the real terminal, editor, preview or an admitted graphical
application. Returning control produces one bounded account of changed files, Git state, commands,
tests, services, usage and governed external effects. The owner chooses whether to resume, redirect,
reassign or explicitly settle the Work. Merely opening or closing a native client resolves nothing.

By programme exit, installed software has a small observable identity independent of the certified
roles it may play. A graphical vendor desktop is supported only if the earlier native terminal and
remote-client paths leave a repeated high-value job unsolved.

## Working vocabulary

- **Application** — installed software in the Company Runtime or an approved host-side client. It may
  expose a CLI, GUI, service, protocol endpoint or several of these.
- **Harness role** — permission to own one delegated agent turn under the complete Runtime Bridge
  launch, event, usage, cancellation and recovery contract.
- **Tool role** — permission to be invoked during Work. Consequential effects still cross Authority.
- **Interactive-client role** — a human-facing interface attached to a harness session or workspace.
- **Certified autonomous** — Restless may delegate unattended Work to the exact admitted build.
- **Governed interactive** — the owner operates the application inside a bounded company scope.
- **Personal interactive** — owner configuration or accounts may enter; output is reconciled before it
  becomes company evidence.
- **Break glass** — deliberately broader manual access after checkpoint, with explicit loss of some
  guarantees and mandatory return inspection.
- **Exact attachment** — the native client controls the same live provider/harness session.
- **Exact resume** — the native client continues the same stored session after autonomous control ends.
- **Reconstruction** — a new native session starts from canonical Restless context and exact workspace;
  it must never be described as the same session.

## Invariants

1. **Restless remains the company canon.** Provider transcripts and application histories are session
   state, not a second Work, Decision or Authority ledger.
2. **Takeover never implies completion.** Only existing typed Work, Attention and owner-decision paths
   settle company state.
3. **One active writer.** Autonomous and human control cannot silently mutate the same attempt or
   worktree concurrently.
4. **Checkpoint before control transfer.** The pre-takeover workspace and process/session identity are
   recoverable even if the native client crashes or the owner abandons it.
5. **Attachment quality is explicit.** Exact live attachment, exact resume, fork, reconstruction and
   workspace-only access are distinct user-visible facts.
6. **No provider root credential enters Runtime merely to improve UX.** Use scoped relay or local
   client authentication; otherwise degrade honestly.
7. **Native means native.** Restless does not rebuild a partial imitation and label it Codex or Claude.
8. **Ordinary files remain ordinary.** The control lease is temporary process/attempt coordination,
   not constitutional file custody or a universal lock manager.
9. **Personal capability does not become autonomous authority.** User plugins, remembered approvals,
   connectors and personal MCP servers remain interactive until separately admitted.
10. **No automatic generalisation.** One working native client does not justify a universal harness,
    application or plugin marketplace.
11. **Return is a first-class path.** A one-way “open terminal” link is not takeover support.
12. **The stronger claim is evidence-gated.** Restless cannot claim to dominate direct harness use until
    the comparative corpus demonstrates lower owner burden without material capability loss.

## Sequence

### Sprint 40 — exact Codex takeover and return

Prove the smallest complete vertical slice using the native Codex App Server already owned by
Restless. The counted owner opens the genuine Codex terminal client against the exact thread and
worktree, intervenes, returns control and sees one reconciled change account.

This sprint proves control ownership and handback before any generic application model exists.

### Sprint 41 — Claude portability without false parity

Apply the observed takeover contract to Claude Code. Prove exact CLI resume if the pinned SDK/session
format supports it. Otherwise ship explicit reconstruction from canonical context. Provider or desktop
authentication that requires a reusable secret in Runtime fails admission rather than weakening the
boundary.

### Sprint 42 — governed application roles

Only after two harnesses exercise the seam, introduce a small application inventory separating an
installed build from its tool, harness and interactive-client roles. Prove install, readiness, update,
rollback, state ownership and trust classification with a small mixed corpus. Do not build discovery,
ratings, arbitrary registry execution or an app marketplace.

### Sprint 43 — optional graphical workstation

This sprint is not automatically activated. First record repeated owner work that the Company
Computer, native terminal, editor/preview and host or SSH client cannot perform well. If that gate
passes, admit one exact vendor desktop application as owner-operated software and prove its lifecycle,
authentication, persistent state and return path. If it does not pass, close the sprint negative and
keep desktops outside the base Runtime.

### Sprint 44 — comparative proof and positioning

Run the same real company outcomes through direct native operation, fully managed Restless and a
managed-to-native-to-managed path. Measure accepted output, owner time, handoff loss, latency, cost,
recovery and residual native-only capability. A fresh reviewer settles a narrow product claim and
removes unsupported copy.

## Cross-programme acceptance corpus

The shared corpus includes:

- a broad hard-goal Attention item that benefits from owner narrowing;
- a subtle repository repair requiring low-level command and context inspection;
- a visual or interactive artifact requiring preview and manual judgement;
- one approved MCP or governed external effect;
- an owner correction delivered during active agent work;
- native-client crash, Runtime restart and abandoned takeover;
- a harness version change between stored session and resume;
- personal plugin or ambient configuration attempting to enter autonomous work;
- two actors or companies attempting to address the same native session locator; and
- return with no material changes.

Every case records the pre-handoff checkpoint, control owner, native session relationship, workspace
change, provider usage where available, canonical Restless changes and cleanup state.

## Programme measures

- seconds and owner actions from **Take the controls** to useful native input;
- percentage of takeovers using exact attachment, exact resume, fork or reconstruction;
- concurrent-writer or wrong-worktree incidents;
- files, commands, effects, usage or decisions lost at return;
- owner minutes and interventions per accepted outcome;
- outcome acceptance compared with direct native and fully managed baselines;
- end-to-end latency and provider/runtime cost;
- sessions abandoned in the native client rather than returned;
- restart and crash recovery time;
- credential, process, port, state-root and transcript residue;
- native capabilities unavailable through the managed path; and
- days from an important provider capability shipping to a usable direct escape path.

Agent benchmark scores, number of supported applications, number of settings and transcript volume are
diagnostic only. They are not programme success measures.

## Activation and stop conditions

- Do not begin Sprint 41 until one complete Codex takeover and return preserves the exact company
  outcome without concurrent mutation or a second canonical transcript.
- Do not begin Sprint 42 if the seam still contains provider-specific company semantics; repair the
  vertical paths first.
- Activate Sprint 43 only after at least three observed high-value interventions require a graphical
  vendor application and cannot be served acceptably by existing terminal, preview, browser, desktop
  attach or host/SSH access.
- Stop any native path that requires a reusable provider root credential in Runtime, silently imports
  ambient authority, cannot identify its workspace/session relationship or cannot be cleaned exactly.
- Do not ship a general executable field, registry URL, dynamic provider package or per-turn harness
  picker as a shortcut.
- Do not publish the Sprint 44 positioning claim if Restless adds material handoff loss, owner burden or
  capability restriction relative to direct use.

## Deliberately out of scope

- an application store or public harness marketplace;
- universal desktop virtualisation or support for every operating system;
- automatically certifying arbitrary ACP agents or installed executables;
- mirroring every Codex or Claude interface inside Restless;
- importing personal provider history as canonical company history;
- simultaneous human and agent writes to one attempt;
- treating native-client exit as approval or Work completion;
- changing the default harness based on one comparison; and
- multiplayer collaboration unrelated to the one-owner takeover journey.

## Makes deletable

At programme exit, delete or retire:

- one-way raw shell links that cannot return or reconcile;
- harness-specific takeover copy and duplicated control state;
- assumptions that an installed binary is automatically an autonomous harness;
- blanket prohibition on owner-operated personal tools inside the company computer;
- any prototype raw provider-key delivery or ambient config reuse;
- claims that wrapper protocol parity equals native capability parity; and
- positioning that describes Restless as merely another agent harness.
