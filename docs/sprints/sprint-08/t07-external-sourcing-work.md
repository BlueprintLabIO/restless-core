# S08-T7 · Source one external capability through ordinary Work

**Layer:** OrgIntel + Runtime + Authority boundary.  
**Serves:** Sprint 08 criterion 14.  
**Depends on:** nothing. This ticket frames the provider Work that T0 executes.  
**Observed friction:** Sprint 08's Airwallex → Wise branch exists in founder-authored prose, while
the live company has no Work showing that it recognised the missing operating-money outcome,
considered internal versus external postures, researched candidates, chose a provider trial or
learned whether to retain it.  
**Makes deletable:** the Exec instruction that every missing capability should become a new Staff
actor, provider-selection reasoning that lives only in sprint prose and any sourcing-specific
workflow/entity introduced before this run needs it.

## Outcome

The selected company treats the operating-money connection as its first explicit external sourcing
experiment. An accountable internal actor frames the required outcome, records which responsibility
the company retains, runs the smallest candidate research/probe, requests consequential authority
through the existing boundary, and evaluates the provider-backed result. The complete path is visible
in ordinary Work, Attempts, decisions and artifact references.

This ticket proves organisational behaviour, not the quality of a generic procurement framework.

## Sourcing posture

Sourcing is model judgement with a finite working vocabulary, not deterministic policy. The Exec may
choose or combine:

```text
do internally
build or automate
buy an input
rent a tool or bounded resource
commission a deliverable
delegate a function
partner
hire or otherwise internalise
```

For Sprint 08 the expected posture is renting an external financial platform while retaining business
judgement, beneficiary control, treasury protection and final payment approval. That is a hypothesis
until the company records the decision from T0 evidence. No cost threshold, keyword or provider name
may select it automatically.

## Scope

1. **Correct missing-capability framing.** The Exec operating context no longer routes every genuinely
   different missing capability directly to `people create`. It first considers reuse, internal
   build/automation, an external input/tool/deliverable/function/partner, or internalisation. Staff
   creation is only the internal-capacity choice.
2. **Keep one internal owner.** The provider is never an OrgIntel Actor and owns no Restless Work.
   One internal actor remains accountable for framing, research, access, acceptance, integration and
   evaluation even when the provider performs most execution.
3. **Use ordinary Work.** Represent the path with the current outcome contracts and only the existing
   `requires`/`revises` semantics. Candidate research becomes a Work branch only when there is evidence
   worth gathering; do not pre-create every supplier or add `researches`, `trials`, `sources` or
   `engages` edges.
4. **Make the decision explicit.** Record, through the existing OrgIntel decision/file surface:

   ```text
   required outcome
   chosen posture
   accountable internal actor
   what the company retains
   what the provider supplies
   alternatives considered
   expected cost/deadline
   trial and acceptance evidence
   authority/data required
   reconsider trigger
   ```

   A structured posture column or new sourcing table is not required for the first run.
5. **Keep execution native.** Public research and provider browsing happen directly in the Runtime.
   T0's report is linked as the exact provider-proof artifact. Account creation, terms, spend,
   credentials and consequential actions use the existing owner handoff/Authority/effect path.
6. **Evaluate the acquisition.** After the selected service is used, record observed usefulness,
   provider confirmation, elapsed time, external/model cost, owner interventions and the decision to
   retain, replace, internalise or stop. A generic five-star provider score is not evidence.
7. **Branch, run, purge.** Airwallex is the first bounded candidate. Wise becomes live Work only if
   Airwallex fails the required contract. Once evidence selects a path, abandon or omit the losing
   branch and delete unused provider-selection machinery.

## Expected Work shape

The exact graph remains the Exec's judgement. A sufficient result resembles:

```text
frame operating-money need
  → research/probe current candidate
  → decide sourcing posture and authority boundary
  → acquire and use selected service
  → evaluate retained external capability
```

These are ordinary Work outcomes. The graph may combine nodes when one actor can produce one accepted
artifact without losing accountability, and may add the fallback probe only when the first result
requires it. Flexibility means the graph follows evidence; explicitness means the need, decision,
trial and evaluation never exist only in an Exec journal or sprint document.

## Verification

- In a `_test` company, give the Exec a missing productive outcome plus bounded candidate evidence.
  Observe internally owned Work for framing, research/trial, decision and evaluation. Exact node count
  and posture choice are behavioural judgement and are not asserted.
- Assert that every resulting Work owner is an existing internal Actor and no provider/counterparty
  Actor was created.
- Assert that the graph uses only existing Work statuses and `requires`/`revises` edges.
- In the selected live company, link T0's sanitized provider report and subsequent provider reference
  to the sourcing Work. A copied documentation claim or `_test` result cannot support the live choice.
- Record one explicit retained/rejected/unused alternative and the event that would reopen it.
- Show that any account/credential/spend request crossed the existing Authority or owner boundary and
  did not acquire permission from the sourcing decision itself.

## Risks

- **The posture list becomes a universal capability algebra — invariant:** it appears in judgement
  guidance and decision evidence only; no Work state, Authority operation or provider interface is
  generated from it.
- **A compliant `_test` world makes a weak provider look proven — invariant:** `_test` proves graph and
  Authority mechanics only. T0 and T6 require provider-native evidence.
- **Research fans out into a provider catalogue — guarded:** only a candidate with a decision-relevant
  uncertainty earns Work. The run retains one canon and records a reconsider trigger for the rest.
- **External execution removes internal accountability — invariant:** one internal actor owns outcome
  acceptance and evaluation throughout.
