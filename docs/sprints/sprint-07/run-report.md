## Landed boundary

- The existing OrgIntel owner handoff now carries one compact authored presentation payload plus
  author, authored time and a deterministic source fingerprint. Work, Attempts, artifacts and gates
  remain the operational/evidence truth.
- One `present-to-owner` skill source is included in both accountable-lead and Exec context. It tells
  the actor to finish machine-doable work, classify the real owner need, separate observation from
  recommendation, preserve uncertainty and ask for the smallest exact action.
- Team members route ordinary judgement to their lead; lead-owned judgement routes to Exec; Exec
  must explicitly admit a current authored brief to the owner. Exec-authored judgement is not
  self-admitting. The five irreducible human categories keep their direct boundary and factual fallback.
- The attention projection maps authored meaning unchanged. It no longer reuses the Work title,
  invents generic “why/recommendation” copy or treats every judgement as an outcome review.
- The source kind selects truthful actions: review acceptance/revision, a recorded bounded decision,
  or a prepared human step. Conversation stays pending until an explicit source-owned transition.
- The cockpit uses one editorial decision folio, a scannable title-plus-ask queue, collapsed source
  evidence and one persistent conversation with the accountable lead. The rail no longer repeats a
  synthetic copy of the selected brief.

The admission gate is deliberately split across existing responsibilities rather than implemented as
a presentation service. The accountable lead authors the meaning after the work and independent
evidence are prepared. Exec checks that the brief is current, supported, consequential and names an
irreducible owner need; it may resolve or return work that has not earned owner attention. The owner
projection then maps only an admitted current brief. It does not rewrite, summarise or improve it.

## Remaining friction

- The initial scripted fixture proved that a linked artifact row is not the same as a reachable
  outcome. The final run must continue to probe the target, not trust metadata.
- The independent critic correctly needed source files, not just confident summary prose. A future
  run may prove that evidence availability deserves an explicit live health state in the projection;
  this sprint does not add speculative evidence custody or a new lifecycle.
- Historic Exec messages remain historic and can contain old implementation-heavy prose. The selected
  brief no longer duplicates them, but history is not rewritten.
- The genuine run proved that grammatically plausible Exec prose can contradict its state transition.
  Context and prompt guidance now name the terminal semantics, but a future sprint should decide
  whether resolution/request contradiction warrants a deterministic invariant after more examples.
- Human comprehension and taste cannot be replaced by an automated score. They remain the explicit
  final founder observation rather than a fake green check.
- Provider quota cooldown can delay an independent actor even when the source, target and Work are
  correctly prepared. The run preserved the failed attempt and resumed on a separately live-probed
  configured failover; it did not let Exec, the UI or the implementer self-certify the brief.
- A reviewer can currently write `CHANGES_REQUESTED` in its artifact while returning
  `outcome_met` in the runtime decision envelope. The lead caught this run, but the two signals need
  one semantic invariant before another sprint relies on automatic downstream release.
- Actor-addressed completion mail currently outranks ready Work and can repeatedly occupy the same
  lead with coordination turns. That is useful for real judgement, but ordinary progress notices
  need coalescing or a lower scheduling priority so they cannot starve the graph they describe.
- Runtime launch refusals currently consume the same attempt budget as an actor that actually ran.
  Three transport-cooldown refusals exhausted the canonical gate node without executing one command,
  so the run had to preserve and rewire its evidence through a replacement node. Launch admission
  should happen before an Attempt spends its retry allowance.
- Validation actors committed evidence reports to the product branch when their prompt did not
  make the `/company/outputs` boundary sufficiently explicit. The debris was removed in this run;
  future review prompts should name the product tree as read-only unless remediation is the Work.
