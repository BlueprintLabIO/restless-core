# Model status, company keys and one Exec conversation

Observed friction: Reno lead chat says Connect a model while the composer names one (#1, #36,
#37); a saved Resend key cannot be used (#2, #12); an item opens another scoped chat (#5, #10);
the reply rules add repeated openers and closing limits (#18, #40, #41).

Layers: Authority owns key bindings and model admission; the cockpit projects their state. OrgIntel
retains the general conversation; an item is linked context rather than a second conversation.

Acceptance:
- The selected agent's route is shared by rail and chip; an Exec admission failure does not
  disable an independently available lead. Missing routes are explained before sending and offer
  no stale Stop control. Include direct/native, checking/error/cooldown and owner/admin/member.
- Existing resend bindings read as resend.production and persist canonically on save. New Vault
  values use that name. Rename preserves the exact value and all existing consumer references;
  collisions, stale revisions, foreign paths and fixed model/finance references are refused.
- Ask Exec links the item into the general conversation. Legacy item-chat links keep that same
  history. Card and document toolbars do not create a parallel discussion; explicit author replies
  still go to their original recipient.
- Remove reply scaffolding while preserving hidden routing and explicit authority boundaries.
  Replay the identical Reno questions before/after with the same model and frozen facts, inspect
  accuracy and links, and retain the actual output and limitations.

Delete: scoped Inbox discussion navigation, duplicate inline discussion toggle/state, the document
Discuss toolbar, the long fixed visible reply template, and the Vault's prohibition on dotted names.

Evidence is recorded in the sprint spec and evidence/reply-comparison.md. Remaining acceptance
scenarios keep the sprint checklist open; compilation alone does not establish completion.
