# Quiet decision worker

The handoff and native-document Undo worker previously read both pending-decision tables for every company every second, even with no work. It now uses the existing cell change notifications and a local wake after a saved decision. It still scans durable rows on startup, uses database time for the next deadline, and performs a two-second repair sweep if a wake is missed. The one-second minimum between due retries avoids a busy loop on an unsuccessfully applied decision.

The isolated, two-company idle comparison in `../evidence/sprint-109-resources/decision-idle/` records 48 due queries in 12 seconds before and 24 due queries plus 12 deadline queries after. Both sides used real PostgreSQL and waited for scans after creating the companies. This is a count of SQL statements, not a measurement of CPU time or production savings; the new deadline query reads both pending tables. The `after.json` binary was built from this change on top of Core `3572b1b56dced440bcefffda5857f94fdb1508c6`, before this evidence was added. Both disposable planes were cleaned up.

`scripts/verify-decision-worker.py` exercises handoff and native review decisions using the real daemon and database: normal completion, Undo leaving the source unchanged after the window, and an expired pending decision applied once after a daemon restart. It confirms the original deadline, and for native reviews checks a single acceptance and requester note. `scripts/verify-decision-idle.py` repeats the measured idle observation. Neither uses a model provider. These tests do not establish production-wide compute savings or the complete resource gate; A0 remains open.
