## Contradiction found in live work

EXP-16's repaired held-out evaluator declared one atomic Runtime gate whose compact receipts are
generated by that gate. The Staff completion brief nevertheless required those receipts to be linked
before the actor could report `outcome_met`. Runtime only executes declared gates after that terminal
decision. Two no-change validation Attempts therefore stopped honestly at an impossible ordering:
gate evidence had to exist before the gate that creates it could run.

This is a first-party completion-contract defect, not a game, NPC, policy, provider or held-out result.
The exact clean repository candidate already existed, and Runtime already knew how to bind its terminal
commit/tree before executing gates; only the cognitive brief contradicted that mechanical path.

## Bounded repair

For non-review repository Work, the bound Attempt brief now states the existing Runtime contract
directly:

- Runtime binds the clean terminal commit and tree as the candidate without model bookkeeping;
- declared gates run only after the cognitive process returns;
- gate-generated evidence need not exist before the actor reports candidate readiness; and
- Runtime alone decides gate pass/fail and retains the resulting evidence.

File and owner-review Work retain their explicit artifact/ReviewTarget requirements. No gate ordering,
candidate binding, promotion, authority, model, product or evidence threshold changed.
