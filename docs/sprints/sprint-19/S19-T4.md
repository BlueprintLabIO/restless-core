# S19-T4 — Say that owner-facing fields are writing

**Outcome:** Every accountable actor is told, at the point where it authors a durable record, that some of
those fields are read by a person and must open with something that person can read.

**Layer:** Prompts and context assembly.

**Observed friction served:** `OwnerBrief` exists because owner handoffs hit exactly this problem: machine
truth is not owner-readable meaning. Work records hit it too, and nothing tells an actor that
`work.outcome`, `work.title`, `work.resolution` or an artifact label will be rendered to the owner. The
result is a page of instructions addressed to a model.

**Change:** One shared instruction, included in both the Exec operating context and the lead conversation
context alongside the existing `present-to-owner` and `converse-with-owner` skills, and referenced at the
`restless work add` instruction where the field is actually written. It requires the owner-facing opening
to be plain, and requires the exact machine contract to stay exact underneath it — the readable opening is
an addition, never a replacement or a softening.

**Acceptance:** The assembled Exec context and the assembled lead context both contain the rule, and the
`work add` guidance names it where the outcome is authored.

**Deletion:** Nothing yet. This is deliberately the cheapest possible test of whether a Work-level
owner-brief field is needed at all: if actors comply, no schema, no second writer, no renderer. Evidence
for or against arrives from the next dogfood run, not from this ticket.

**Evidence:** Context-assembly tests asserting the exact rule reaches both surfaces. Model compliance is a
Dogfood 3 observation and is not claimed here.
