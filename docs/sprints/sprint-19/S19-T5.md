# S19-T5 — A prepared outcome the cockpit can actually open

**Outcome:** Every ReviewTarget an accountable actor can reasonably choose either opens natively in the
owner cockpit, or says exactly what it is and shows the recorded evidence. No dead ends.

**Layer:** Company Runtime (bounded read-only observation) plus the owner cockpit review surface.

**Observed friction served:** On the live `restyle` company the accountable actor prepared
`/company/outputs/redesign/2026-08-larder-sample/index.html` — a finished, self-contained 23,114-byte
web page — and linked it as the ReviewTarget. The cockpit told the owner:

> **The website is not ready yet.** This outcome does not have a directly reviewable website.

It was looking straight at the website. `attention::project` recognised exactly two kinds of target: a
loopback HTTP service (`runtime_http_target`) and a Markdown/plain-text file
(`is_runtime_review_text_target`). Everything else fell to `_ => None`, and the cockpit then rendered a
heading claiming the outcome was not ready — which is not the same statement as "we cannot open this",
and in this case was simply false.

`ARCHITECTURE.md`'s outcome-native review names "a live site in the shared browser, playable game build,
rendered document/PDF/image, audio or video player" as the native experiences. Only two of those could
ever reach the owner.

**Change:** A third ReviewTarget kind, `runtime-file`: one produced file beneath `/company` in a format
a browser displays, served through the existing isolated review origin. The review ticket already
carries ticket authentication, an expiry, generation pinning and header hygiene; a file review reuses
all of it and only changes where the bytes come from. A page's own stylesheet, scripts and images are
served with it, confined to the ReviewTarget's own directory. When no target can be opened, the cockpit
says that plainly, names the exact URI, and lists the evidence the company did record.

**Acceptance:** A produced `index.html` opens in the review frame with its own assets; a PDF, image or
recording opens; a Markdown target still renders as a document rather than a frame; a path outside the
prepared outcome's directory is refused; a format the cockpit cannot display is refused rather than
framed blank; a target larger than the review limit fails honestly; and an item with no openable target
shows what exists instead of a false "not ready".

**Deletion:** The `_ => None` dead end and the "does not have a directly reviewable website" copy.

**Evidence:** Focused traversal, format and boundary tests; the exact `stat`/`head` reads proved against
the real `restyle` ReviewTarget; and a cockpit render of a file-backed review.
