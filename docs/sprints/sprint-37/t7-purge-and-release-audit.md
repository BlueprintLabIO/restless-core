# S37-T7 — Purge experiments and release one canon

**Layer:** Cross-layer simplification and release audit

## Observed friction served

Provider experiments easily leave source-build deployments, raw Compose variants, diagnostic domains,
temporary screenshots, duplicated invitation paths and stale workloads. Keeping them all would turn
one proven access fabric into several ambiguous ways to publish.

## Outcome

Select the passing provider/access shape, delete every superseded diagnostic path and update the Core,
Cloud, Runtime and owner-facing documents to one source-owned contract. Preserve compact negative
evidence and results, not runnable alternatives.

## Acceptance

- One provider supervisor, endpoint resolver, invitation exchange and access descriptor remain canon.
- Direct Runtime exposure, generic application deployment and `sslip.io` release paths are absent.
- Temporary apps, containers, networks, routes, ports, image tags, invitation keys, screenshots and
  generated test artifacts are removed by exact ownership.
- Repository status contains no sprint-generated junk or secret material.
- Core/Cloud compatibility probes and all affected tests pass from clean checkouts.
- Architecture and component specs are updated only for evidence-backed settled decisions; blocked or
  negative findings stay explicit.
- The final report includes exact external evidence, costs, owner interventions, accepted risks and
  remaining profile limits.

## Makes deletable

All losing deployment branches, redundant docs, manual cleanup instructions and claims unsupported by
external evidence.
