# S37-T0 — Freeze the access corpus and transfer case

**Layer:** Cross-layer evaluation contract

## Observed friction served

Cloud 14 proved that a local fixture, public HTTP response and provider-reported deployment can each
look successful while public UDP, owned identity or isolation is still unproved. The sprint needs one
frozen definition of “another person can use the exact artifact” before implementation changes the
question.

## Outcome

Commit a versioned corpus containing:

- the exact Sprint 36 web and Swift Arrival candidates;
- one unseen HTTP/WebSocket transfer candidate selected only after the fabric is frozen;
- browser and native-client journey inputs and expected native outcomes;
- invitation cases for valid, revoked, expired, tampered, cross-company, wrong-subject, wrong-build and
  wrong-protocol access;
- restart, ambiguous-result, ceiling and cleanup cases; and
- an evidence schema that distinguishes provider observation, external-client observation and claim.

The transfer candidate must use the released profile without Restless-specific source changes beyond
its service manifest.

## Acceptance

- Corpus digests are pinned before T3 implementation begins.
- Every positive case names the external observer and native success condition.
- Every negative case names the boundary expected to refuse it.
- Unknown resource and network measurements have an explicit representation.
- Cloud 14's unpassed gates remain visible prerequisites rather than being relabelled as Sprint 37
  coverage.

## Makes deletable

Ad hoc curl transcripts, mutable test URLs and prose-only claims that a deployment is “reachable.”
