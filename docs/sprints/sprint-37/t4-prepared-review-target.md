# S37-T4 — Prepare the native review target

**Layer:** OrgIntel + Runtime Bridge + Owner Cockpit

## Observed friction served

A technically reachable endpoint still returned setup work to the reviewer: choose a build, find a
port, copy a token, enter launch arguments and decide whether the result belonged to the accepted
Attempt.

## Outcome

Turn the authoritative ready receipt into one Work-linked `ReviewTarget` projection. Browser targets
open at the useful state. Game targets offer the compatible exact build or launcher payload with join
discovery already configured. The view states the audience, expiry, candidate and material health or
cleanup debt in ordinary language.

## Acceptance

- The target links exact Work, revision, Attempt, artifact digest, publication and accountable lead.
- A reviewer reaches native use without provider knowledge, manual DNS/port/token entry or Runtime
  attachment.
- Changed candidate or superseded publication cannot silently reuse an old target.
- Degraded, expired, revoked, failed and cleanup-pending states remain honest and actionable.
- Provider IDs, gateway internals, raw logs and infrastructure controls remain progressive diagnostic
  detail rather than the primary surface.
- Owner judgement resumes the existing Work/handoff path; no second review lifecycle is introduced.

## Makes deletable

README launch recipes, copied terminal commands and PaaS-style configuration as the normal review
surface.
