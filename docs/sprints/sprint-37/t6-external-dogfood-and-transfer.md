# S37-T6 — Run external native dogfoods and the transfer case

**Layer:** End-to-end evaluation

## Observed friction served

Local containers and same-host clients can validate protocol code while missing public DNS, TLS,
firewall, NAT, client packaging and independent-network failures. One project can also hide
special-casing in supposedly generic infrastructure.

## Outcome

Run the frozen corpus from independent client environments against exact immutable deployments:

1. a human uses the web demo over owned HTTPS/WSS;
2. two native Swift Arrival clients join one authoritative UDP server and observe the same host-owned
   state; and
3. the held-back HTTP/WebSocket application transfers without platform code changes.

Capture native outcome evidence, route/build identity, provider observations, elapsed time, owner
interventions, cost, connection behaviour and teardown.

## Acceptance

- Clients are outside the provider host and company Runtime network.
- Browser evidence includes certificate, admission, WSS upgrade and native scenario completion.
- Game evidence includes two distinct subjects, server-side admission and shared authoritative state.
- The transfer artifact uses the same released manifest/profile and provider supervisor unchanged.
- A human completes each prepared journey without infrastructure instructions.
- Every run ends with the T5 absence proof.
- Results distinguish product quality from network/publication capability; a reachable unplayable game
  is not reported as a game-quality pass.

## Makes deletable

Same-host “external” tests, simulated player claims and special Swift Arrival deployment code.
