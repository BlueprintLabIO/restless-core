# S10-T4 · Dogfood, compare against the baseline and purge

**Layer:** End-to-end evaluation across owner cockpit, gateway and Company Runtime.

**Observed friction:** Sprint 09 left rendered desktop review open, and attractive replacement stacks
can otherwise be selected from documentation without proving that the existing stack failed.

## Outcome

One `_test` company run demonstrates the corrected owner experience, control boundary, prepared
handoff and multi-application desktop. The run report records concrete remaining friction and makes
one transport decision: retain the corrected stack or open a replacement comparison because a named
workload still fails.

## Acceptance

- Headless checks, production build and focused authority/attachment tests pass.
- Doctor reports the reconciled `_test` Runtime and its actual supervised processes.
- Rendered desktop dimensions are recorded at 390, 768 and 1440 CSS pixels.
- Observer, sole controller, competing owner, resize, reconnect and return are exercised.
- Chromium plus PCManFM completes a useful file/browser task against persistent state.
- One prepared human-step handoff preserves its requested action through attach, takeover, return and
  source observation without owner self-attestation.
- One native outcome review bypasses the desktop.
- Beautiful UI, Cult UI and one source-first Svelte reference are consulted during final polish.
- Copied URLs, superseded layout rules, unused shell components and failed alternative branches are
  deleted before the checklist closes.
- The report names any latency, fidelity, audio, high-motion, GPU or computer-use failure that would
  justify testing Wayland/Selkies; absence of such evidence keeps that migration out of scope.

## Prior machinery made deletable

- stale Sprint 09 claims that a rendered full-canvas desktop was already proved;
- replacement-stack speculation unsupported by a failed company scenario;
- any implementation branch not selected by the final run.
