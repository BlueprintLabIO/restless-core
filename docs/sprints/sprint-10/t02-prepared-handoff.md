# S10-T2 · Keep the prepared action attached to the live computer

**Layer:** OrgIntel projection and owner cockpit presentation.

**Observed friction:** The prepared Attention focus names the Work but gives permanent prominence to
transport state and conversation chrome while the exact requested owner action is easy to lose. The
owner can return control beside that context without a strong visible distinction from completion.

## Outcome

The live Company computer carries the source-owned handoff title, exact requested action,
responsible actor and Work-scoped conversation. Control actions describe only input ownership. Owner
judgement and externally observed completion remain in their existing source-owned paths.

## Acceptance

- The focused desktop is URL-addressable and recoverable after reload while the handoff remains open.
- `requested_action` is readable without opening logs, evidence details or the generic Company page.
- The responsible actor remains named and receives the existing return-control notification.
- Take and Return controls explain that they do not complete Work or the human step.
- A review decision remains Accept outcome / Request changes in the review surface.
- An observable human step exposes no “I’m done” control merely to advance state.
- A native `ReviewTarget` continues to open before any desktop fallback.

## Prior machinery made deletable

- local-only prepared-focus state that disappears on reload;
- transport-first uppercase copy that crowds out the owner’s actual task;
- any implication that Return control is a completion acknowledgement.
