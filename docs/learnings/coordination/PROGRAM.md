# Communication frontier research programme

Status: approved experimental direction; no wildcard is a production default

## 1. Objective

Find whether new context, communication and cognitive topologies can move the point at which an
accountable team lead benefits from adding other minds.

Before any wildcard, execute the ordinary-team crossover in [`BASELINES.md`](BASELINES.md). Wildcards
target measured communication bottlenecks; they are not the first attempt to discover whether normal
delegation works.

The programme preserves the settled company structure in every arm:

```text
Owner
→ continuously available Exec
→ one accountable team lead per executable request
→ experimental organisation below the lead
```

Exec dispatch latency and post-dispatch availability are measured invariants. The experiment never
uses Exec as the strong-singleton producer. The main production baselines are:

- **B0 — lead alone:** one strong accountable lead owns the complete outcome;
- **B1 — ordinary handoff:** the same lead commissions one worker through a bounded brief and later
  integrates its artifact;
- **B2 — lead plus independent critic:** B0 followed by artifact-only independent review.

Each wildcard changes one important mechanism below the lead and is compared with the relevant
baseline in the same harness.

## 2. Questions

1. Can shared history remove briefing and reintegration cost without amplifying correlated mistakes?
2. Can agents coordinate primarily through observable work rather than messages?
3. Can one cognitive owner use parallel execution without maintaining several competing project models?
4. Can communication become exception-driven rather than continuous?
5. Can the system select leaders and collaborators from cheap evidence rather than fixed roles?
6. Which mechanisms generalise from code to research, documents and live operations?

Task hours are recorded but are not the primary explanatory variable. The candidate predictors are:

- decomposition into independently acceptable artifacts;
- shared mutable state and interface volatility;
- tool density and environment discovery cost;
- strength of the lead-alone baseline;
- uncertainty and need for independent evidence;
- communication bandwidth required before integration;
- latency that can genuinely overlap;
- cost of detecting and repairing a bad contribution.

## 3. Staged method

### Stage 0 — Comparable foundation

Before counting wildcard outcomes:

1. Separate Exec and team lead in the harness.
2. Prove Exec dispatches, quiesces and accepts a second concurrent request while the first lead runs.
3. Freeze B0, B1 and B2 launch contracts, tool sets, time envelopes and result ingestion.
4. Add explicit accounting for lead/worker/communication tokens, cached input, tool calls, artifact
   events, redundant reads, integration changes and Exec occupied time.
5. Fix artifact-first recovery, declared evaluator fixtures and runtime capability manifests when they
   affect comparability; do not add unrelated coordination machinery.
6. Run one matched B0/B1/B2 calibration on the existing Cosmon seed.

Exit: the same starting state produces inspectable reports in all three arms, Exec remains available,
and a missing callback remains `unknown` while observable artifacts survive.

### Stage 0.5 — Ordinary-team crossover

Run the sparse coding/research size × parallelisability calibration in `BASELINES.md`, refine only the
observed decision boundary, and test larger teams only where one worker already adds value. Record the
ordinary frontier before implementing W01–W16.

### Stage 1 — Mechanism probes

Exercise every wildcard on the smallest scenario capable of falsifying its mechanism. A probe may be
deterministic when testing context reconstruction, event delivery or runtime state cloning. Cognitive
claims require a live model and native artifact.

Each wildcard gets:

1. one deterministic/conformance probe where applicable;
2. one live matched pair against B0 or B1;
3. a `provisional-win`, `provisional-loss` or `blocked` decision.

Do not run three expensive replicas of an idea that cannot pass its basic mechanism or first outcome
comparison.

### Stage 2 — Replication on different work shapes

Provisional winners receive at least three order-randomised matched trials across:

- **high coupling:** one integrated Cosmon gameplay/product slice;
- **parallel breadth:** sourced research with several independent evidence regions;
- **clean components:** a document, data or product outcome with explicit native sub-artifacts.

At least one trial uses a different model/provider pairing. Model choice is recorded separately from
the organisational mechanism.

### Stage 3 — Cross-domain generalisation

Survivors advance through the real portfolio:

- **Cosmon:** executable product and visual/interactive judgement;
- **Aris `_test`:** mechanism-only research/outreach preparation with fiction isolated from live
  company memory, followed by a bounded real task when safe;
- **Thymelake:** document/browser/operational handoff with provider-observed state, initially without a
  consequential live effect unless separately authorised.

An idea that wins coding but loses research or operations remains a scoped pattern rather than a
general OrgIntel default.

### Stage 4 — Routing policy

Using only observed run features, fit the smallest understandable routing rule that predicts:

```text
lead alone
| lead + critic
| lead + parallel hands
| lead + autonomous Staff
| lead + one of the winning communication patterns
```

Begin with model judgement over the measured situation, not a hard-coded score. A deterministic router
is justified only after repeated outcomes expose a stable rule.

### Stage 5 — Promote and purge

For each survivor:

- promote the learning and its scope to `CANON.md`;
- add or revise an OrgIntel teamwork default only if real runs need it;
- write an ADR only for a consequential enduring architectural choice;
- delete losing adapters, flags and duplicate communication paths;
- retain small reproducible probes and run reports, not every generated trace.

The programme ends with fewer production modes than it started with.

## 4. Wildcard experiment cards

### W01 — Session mitosis

- **Hypothesis:** a lead and worker forked from one exact shared task history will reach useful work
  faster and require less reintegration than an ordinary brief/handoff.
- **Comparison:** B1 versus identical models/tools with a hashed common prefix and role-specific
  post-fork instructions.
- **Smallest test:** jointly inspect one current product slice, agree one artifact seam, fork, produce
  two non-conflicting contributions and integrate them.
- **Win signal:** lower orientation/communication tokens and redundant reads, no worse native outcome
  or integration rework.
- **Primary risk:** shared history creates correlated blind spots or retains irrelevant context.

### W02 — Fork–work–reunite cycles

- **Hypothesis:** periodic semantic checkpoints preserve mutual understanding more cheaply than
  continuous messaging.
- **Comparison:** W01 one-shot fork versus fork → independent artifacts → fresh reunion → re-fork.
- **Smallest test:** two development cycles around a changing interface.
- **Win signal:** fewer late interface collisions without chat volume approaching B1.
- **Primary risk:** reunion context becomes a costly global re-read.

### W03 — Exec-to-lead lineage fork

- **Hypothesis:** a neutral request capsule forked from executive intake transfers owner intent more
  faithfully than an Exec-authored brief while letting Exec return immediately.
- **Comparison:** ordinary Exec brief versus forked neutral request context.
- **Smallest test:** dispatch two concurrent department requests and test lead comprehension plus Exec
  availability.
- **Win signal:** fewer clarification/reframing turns with no executive context or authority leakage.
- **Primary risk:** role confusion, excess portfolio context or capability leakage. A redaction and
  tool-authority audit is mandatory before live-company use.

### W04 — One brain, many hands

- **Hypothesis:** one lead retaining the whole causal model can use parallel bounded executors more
  effectively than autonomous coauthors on tightly coupled work.
- **Comparison:** B0, B1 and one lead session dispatching parallel inspect/build/test/render operations
  that return observations or artifacts but own no project theory.
- **Smallest test:** a coupled code/visual slice with two genuinely overlapping tool latencies.
- **Win signal:** lower wall time than B0 and lower integration/replay cost than B1 at equal quality.
- **Primary risk:** the lead becomes a serial cognitive bottleneck and “hands” are too weak to produce
  independent value.

### W05 — Shared semantic blackboard

- **Hypothesis:** a bounded shared situation model replaces most status traffic while preserving the
  facts needed for coordination.
- **Comparison:** B1 messages versus patch operations over objective, current interfaces, discoveries,
  uncertainties and decisions.
- **Smallest test:** two workers whose artifacts depend on one evolving interface.
- **Win signal:** fewer communication tokens and stale assumptions without loss of provenance.
- **Primary risk:** the blackboard becomes a second plan/database or an untrusted agent overwrites truth.

### W06 — Causal context deltas

- **Hypothesis:** an actor with a known base checkpoint needs only causally relevant changed facts and
  artifacts, not a replayed transcript.
- **Comparison:** full bounded context refresh versus base hash + exact delta.
- **Smallest test:** resume a worker after two material upstream changes and one irrelevant event.
- **Win signal:** correct action with materially fewer input tokens and no extra source rediscovery.
- **Primary risk:** the delta compiler silently omits a dependency or converts `unknown` into absence.

### W07 — Proof-carrying handoffs

- **Hypothesis:** an artifact bundled with its exact inputs, runnable proof, semantic diff and review
  target requires less explanatory communication and produces safer acceptance.
- **Comparison:** prose result message versus proof-carrying artifact.
- **Smallest test:** one producer → lead integration handoff with a hidden integration defect.
- **Win signal:** faster accurate acceptance/rejection and less producer explanation.
- **Primary risk:** proof checks only an implementation proxy and creates false confidence.

### W08 — Ambient coordination

- **Hypothesis:** material filesystem, Git, test, browser and decision events can trigger the right
  actor without peer status messages.
- **Comparison:** explicit update messages versus subscriptions to typed artifact/interface events.
- **Smallest test:** upstream interface changes once, dependent actor must adapt without polling.
- **Win signal:** correct timely wake, zero status chasing and bounded irrelevant events.
- **Primary risk:** noisy events recreate polling or the observer misses semantic change.

### W09 — Questions-only communication

- **Hypothesis:** restricting peer traffic to unresolved question, blocker, interface change and
  terminal artifact removes narration without harming coordination.
- **Comparison:** ordinary free-form B1 messaging versus restricted semantic channel.
- **Smallest test:** one separable producer and one integration owner.
- **Win signal:** lower communication volume with no increase in late surprises or rework.
- **Primary risk:** useful weak signals are suppressed until they become blockers.

### W10 — Blind sibling diversification

- **Hypothesis:** a common prefix plus deliberately different private evidence/tools retains grounding
  while producing genuinely independent insight.
- **Comparison:** identical forked siblings versus evidence-diversified siblings.
- **Smallest test:** two competing product/research hypotheses judged blind from native outputs.
- **Win signal:** more decision-relevant disagreement and a better selected outcome at acceptable cost.
- **Primary risk:** artificial difference lowers competence or produces incomparable work.

### W11 — Cross-finish

- **Hypothesis:** swapping branches midway reveals and may reduce hidden private context before final
  integration.
- **Comparison:** actors finish their own branches versus actors inherit and finish each other's.
- **Smallest test:** two similar bounded components with a prepared midpoint checkpoint.
- **Win signal:** low takeover latency predicts robust handoffs; discovered hidden knowledge improves a
  later ordinary run.
- **Primary risk:** the diagnostic is intrinsically inefficient and should remain an occasional test,
  not a default process.

### W12 — Micro-audition before ownership

- **Hypothesis:** cheap grounded probes select a better lead/collaborator than model reputation or a
  static role assignment.
- **Comparison:** preselected lead versus two candidates given the same bounded observation task.
- **Smallest test:** inspect the candidate and propose one verified next slice within a strict call
  budget; winner owns production.
- **Win signal:** selected actor subsequently beats the fixed choice enough to repay audition cost.
- **Primary risk:** auditions optimise presentation or local speed rather than long-horizon ownership.

### W13 — Speculative shadow branch

- **Hypothesis:** a sealed alternative creates valuable resilience or option value without continuous
  communication overhead.
- **Comparison:** B0 versus B0 plus a cheaper shadow revealed only on primary stall/failure or terminal
  comparison.
- **Smallest test:** a task with two credible architectures and one injected primary dead end.
- **Win signal:** lower recovery time or materially better choice, including the shadow's full cost.
- **Primary risk:** routine duplicate spend with too few real rescues.

### W14 — Adaptive communication gates

- **Hypothesis:** observable interface divergence, blocked uncertainty or collision risk can decide
  when a rendezvous is worth its cost.
- **Comparison:** fixed communication cadence versus event-opened rendezvous.
- **Smallest test:** a run containing long independent work followed by one genuine coupling event.
- **Win signal:** the gate stays closed during independence, opens before costly conflict and reduces
  total coordination.
- **Primary risk:** the trigger requires the semantic judgement it is meant to save or fires too late.

### W15 — KV-state cloning

- **Hypothesis:** cloning provider/runtime attention state at a common prefix reduces fork latency and
  input throughput beyond ordinary prompt caching.
- **Comparison:** transcript replay, cached-prefix fork and true state clone where supported.
- **Smallest test:** identical long shared prefix with two short divergent tasks.
- **Win signal:** lower time-to-first-token and processed input with identical task behaviour.
- **Primary risk:** no supported runtime exposes safe cloning; a feasibility block is not evidence
  against shared-history value.

### W16 — Common room, private offices

- **Hypothesis:** brief artifact-bound shared sessions followed by long private execution capture the
  value of team alignment without continuous group chat.
- **Comparison:** continuous B1 communication versus fixed or event-driven common-room rendezvous.
- **Smallest test:** kickoff, one interface decision and final review across two private branches.
- **Win signal:** equal/better outcome with fewer shared turns and lower context replay.
- **Primary risk:** meetings become ceremonial or shared history destroys critical independence.

## 5. Measurements

### Outcome

- native artifact acceptance and severity-ranked defects;
- executable/provider-observed success criteria;
- blind owner/expert preference where judgement is required;
- first useful artifact and accepted final outcome time.

### Coordination

- time from request to lead ownership;
- Exec occupied time after dispatch and ability to accept a second request;
- communication turns/tokens by sender and receiver;
- shared-prefix, cached and newly processed input tokens;
- redundant reads/searches and repeated environmental discovery;
- clarification, blocker and interface-change count;
- integration diff, conflicts, regressions and repair turns;
- stale-context and duplicate-work failures;
- time dormant while useful parallel work was available.

### Economics and robustness

- model/tool/compute cost even when nominal price is zero;
- wall time and serial model time;
- owner interventions by taxonomy;
- recovery after missing callback, provider failure and stale input;
- maximum realised authority/alignment failure;
- implementation and operating complexity added by the wildcard.

No single aggregate score decides the result. A report states the trade-off and acceptance judgement.

## 6. Fairness and anti-leak controls

- Same scenario bytes, start ref, success contract, tools and evaluator across matched arms.
- Same strong lead model and comparable total inference envelope unless model diversity is the tested
  variable.
- Fresh sessions/checkouts with exact lineage recorded; no branch may inspect another arm.
- Randomise arm order and record host/cache conditions.
- Freeze harness revision for a matched set; harness repairs restart the set when they could affect the
  claim.
- Withhold producer reasoning from critics unless shared reasoning is itself the tested mechanism.
- Native artifact review precedes reading organisational narration.
- Controlled inputs live only in `_test`; real-world claims require real sources.
- Provider/runtime failure is reported separately and never scored as team refusal or task failure.

## 7. Decision gates

### Mechanism viable

The claimed information or event reaches the intended actor with provenance, truthful unknowns and no
authority leakage. Otherwise status is `blocked` or `provisional-loss` depending on whether the idea or
only its implementation failed.

### Provisional win

One matched run shows either:

- better accepted native outcome without material extra owner attention; or
- at least 20% lower communication/orientation/integration cost with non-inferior outcome; or
- materially faster recovery whose value exceeds the wildcard's full cost.

These thresholds are screening rules, not universal product invariants.

### Replication

A provisional winner must survive three matched trials, including a different work shape, without one
catastrophic integration, authority or epistemic failure attributable to the mechanism.

### Promotion

Promote only when the mechanism:

- beats the relevant simple baseline in at least two work shapes;
- has a clear “use when / avoid when” boundary;
- can be observed and repaired when wrong;
- improves accepted output, owner attention, time or cost enough to repay product complexity; and
- makes a losing path deletable.

Otherwise keep it scoped, reject it or record it as blocked. Do not ship sixteen modes.

## 8. Execution order

| Wave | Experiments | Reason |
|---|---|---|
| **0** | B0/B1/B2 and Exec→lead concurrency | Establish corrected architecture and fair baseline |
| **1** | W01, W07, W09, W04 | Highest expected information and lowest dependency |
| **2** | W02, W05, W06, W08 | Shared checkpoints, state and event communication |
| **3** | W10, W11, W12, W13 | Independence, transferability, allocation and redundancy |
| **4** | W14, W16 | Adaptive/temporal policies require earlier signals |
| **5** | W03, W15 | Highest authority/runtime feasibility risk; test after fork semantics are understood |
| **6** | Cross-domain replication and router | Generalise only the survivors |

Within a wave, run the cheapest discriminating probe first. Stop a losing branch; do not finish the
table merely for completeness.

## 9. Knowledge-base update after every run

1. Store the frozen contract and immutable report under `experiments/<id>/` or link the harness run.
2. Update the experiment's single row in `REGISTRY.md`.
3. Add failure codes from `FAILURES.md`; add no new code for a one-off wording preference.
4. Add or update an evidence link in `EVIDENCE.md`.
5. Change `CANON.md` only if the run changes confidence, scope or routing.
6. Record the next discriminating run or stop decision.
7. After a wave, run a fresh-context simplification review and delete losing machinery.

The knowledge base is successful when a future lead can choose the next team shape without rereading
all transcripts—and when new contradictory evidence can change that choice cleanly.
